Single mmap Initialization

Calls mmap exactly once during Mem_Init, dynamically rounding up to the host getpagesize(). Repeated calls return -1 and set m_error = E_BAD_ARGS.

Immediate O(1) Coalescing

Bidirectional physical neighbor links (prev_phys, next_phys) allow instant zero-search merging on Mem_Free, completely eliminating external fragmentation.

Address-Ordered First-Fit

Maintains an address-sorted doubly linked free list. Splitting triggers only if the remaining space is ≥ 56 bytes (48 B header + 8 B payload), preventing unusable micro-slivers.

Interior Pointer Safety

Supports freeing valid interior offsets (payload_start ≤ ptr < payload_end). Pointers to headers, out-of-bounds, or already-freed blocks return -1 and trigger E_BAD_POINTER.

Zero context switches & no runtime kernel transitions

libmem.so calls mmap() strictly once during Mem_Init(), dynamically rounding up to the host page size (16 KB on Apple Silicon). All subsequent allocations, splits, and coalescing happen strictly in user-space virtual memory without any kernel traps.

3. Trailing Canary Buffer Overrun Guard

0xDEADBEEFCAFEBABE halts silent memory corruption

Every allocated block arms an 8-byte trailing canary footer immediately following the payload. On Mem_Free(), this canary is checked; any write overrun immediately sets m_error = E_PADDING_OVERWRITTEN (3), preventing remote code execution (RCE).

libmem.so (O2) Catches buffer overruns immediately on free; returns -1 and leaves heap undamaged.

Why 48 Bytes? Structure Alignment & Invariant Proof

On 64-bit systems (ARM64 / x86-64), pointers are 8 bytes. Combining size_t size (8 B), int is_free (4 B) + uint32_t magic (4 B), and four pointers (prev_phys, next_phys, prev_free, next_free = 32 B) sums to exactly 48 bytes ($8 + 4 + 4 + 8 + 8 + 8 + 8 = 48$). Since $48 \pmod 8 = 0$, every header preserves perfect 8-byte alignment for both metadata and returned payload pointers without wasting padding.
